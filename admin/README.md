# ELSDR 홈페이지 관리

관리자 화면: https://elsdr-lab.github.io/admin/

1. GitHub에서 연구실 조직에 접근할 수 있는 본인 계정을 사용합니다.
2. Fine-grained personal access token을 만듭니다. Resource owner는 `elsdr-lab`, 저장소는 `elsdr-lab.github.io`만 선택하고 Contents: Read and write를 허용합니다. 만료일을 정하세요. 조직 정책에 따라 Owner 승인이 필요합니다.
3. 관리자 화면에서 토큰을 입력합니다. 토큰은 페이지 메모리에서만 사용하고 파일·localStorage·sessionStorage·쿠키에 저장하지 않습니다. 닫거나 새로고침하면 다시 연결해야 합니다.
4. 원하는 메뉴에서 내용을 수정한 뒤 저장합니다. GitHub가 쓰기 권한을 확인하고 기록을 남깁니다. 공개 홈페이지 반영까지 몇 분이 걸릴 수 있습니다.

## 관리 범위

- 첫 화면 문구: home-records.js
- 구성원·저술: people-records.js
- 연구성과: research-records.js
- 행사·활동: life-records.js
- 연구자료: study-resources.js
- 연락처·모집: contact-records.js
- 사진: PNG/JPG/WebP, 4MB 이하. 업로드 후 항목도 저장하세요.

디자인과 ABOUT 상세 배치는 기존 코드에서 관리합니다. 이 화면은 공개 콘텐츠 편집용이며 비공개 개인정보를 저장하는 시스템이 아닙니다. 사이트와 저장소는 공개입니다. 데이터 파일의 변수명과 JSON 형식을 유지하세요.

## 충돌·복구

다른 관리자가 같은 자료를 수정한 경우 SHA 검사를 통해 덮어쓰기를 중단합니다. 입력 내용을 복사해 둔 후 다시 불러오세요. 저장은 main 브랜치의 GitHub commit으로 기록됩니다. 잘못 저장했을 때는 GitHub 변경 기록에서 이전 파일을 복구할 수 있습니다. 공개된 사이트가 바뀌기 전에 보이는 저장 성공은 저장소 반영 완료를 뜻하며, Pages 배포 성공을 보장하지 않습니다.

토큰 연결·실제 게시에는 유효한 관리자 자격이 필요합니다. 초기 설치 검증에서는 사용자의 토큰을 발급하거나 수집하지 않았습니다. 계정 인수인계 때 후임자가 본인 토큰을 발급하고 전임자 토큰·조직 권한은 회수하세요. 일반 GitHub 로그인만으로 쓰는 OAuth 방식은 별도 서버 및 앱 등록이 필요하며 이 버전에는 포함되지 않습니다.

공식 참고: https://docs.github.com/en/rest/repos/contents

## Research Archive 전용 입력 화면

- ‘연구성과’에서 **Projects** 및 **Publications** 탭을 선택하고, 해당 자료를 추가하거나 수정합니다.
- 기본 입력 필수 항목: 제목, 연도(1900–2100), 4개 연구영역 중 하나. 미완성 자료는 **임시저장** 상태로 저장할 수 있습니다.
- **홈페이지 미리보기**는 공개 Research Archive의 목록과 상세 영역에 사용되는 동일한 렌더링 함수 및 CSS를 재사용합니다. 브라우저 폭이나 관리자 컨테이너에 따라 줄바꿈은 달라질 수 있습니다.
- **임시저장** 및 **공개하기**는 상태를 설정한 뒤 GitHub 저장 확인창을 엽니다. 기존 상단 ‘변경 내용 저장’ 버튼으로도 같은 데이터를 저장할 수 있습니다.
- 기존 연구성과 10건은 별도의 상태 필드가 없어도 ‘공개’로 간주합니다(하위 호환성). 새 항목은 기본적으로 ‘임시저장’ 상태입니다.
- Research Archive는 status=draft, status=archived 항목을 목록과 필터에서 제외하고 공개 자료만 표시합니다.
- **주의:** GitHub 저장소가 공개되어 있어 ‘임시저장’은 사이트 목록에서 숨기는 것일 뿐, GitHub 소스에서 비밀로 보호하는 기능이 아닙니다. 개인정보·비공개 프로젝트 정보는 입력하지 마세요.
- 연구성과 데이터는 기존 research-records.js 한 파일을 유지하며, 관리자 페이지가 기존 GitHub 버전 검사 및 변경 이력을 그대로 사용합니다.

## Research 관리자 페이지와 공개 사이트 일치 (2026-11-04)

- Research 편집기에서 공개 사이트와 같은 **All / Projects / Publications**, **Climate / Ecosystem / Coastal / Regional**, **Year**, **검색** 구조를 제공합니다.
- 관리자 목록과 미리보기는 공개 사이트의 `research-record-view.js` 및 `research-archive.css`를 직접 사용합니다. 별도 모사 마크업을 유지하지 않습니다.
- 실제 페이지의 목록 표시 요소는 **연도, 유형, 제목, 지원기관(프로젝트)/학술지(논문)** 입니다. 입력폼 01은 이에 맞췄습니다.
- 펼침 상세 영역은 공개 페이지의 순서에 맞춰 입력폼 02에서 관리합니다. 중복되는 연도·지원기관·학술지 정보는 한 번만 입력합니다.
- 프로젝트 키워드는 현재 화면에 직접 출력되지 않고 검색 조건에만 사용합니다. 논문 키워드는 상세 화면에도 출력됩니다.
- 저장된 임시저장 자료는 관리자 화면에서만 목록으로 표시하며 공개 사이트에서는 목록/검색 대상에서 제외합니다. **GitHub 소스는 여전히 공개**입니다.
- 공개 홈페이지의 행과 상세 영역을 렌더링하는 코드를 바꿀 때는 공유 모듈을 수정해 두 화면의 불일치를 방지하세요.
